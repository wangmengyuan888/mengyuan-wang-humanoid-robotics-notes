## 重点概念

### 什么是人-机器人交互（HRI）？

人-机器人交互（Human-Robot Interaction，HRI）是研究人与机器人之间信息交换和相互影响的跨学科领域。它超越了传统的图形用户界面（GUI），旨在构建一种更自然、更直观、更具情感的沟通方式，让机器人成为真正的“伙伴”而非冰冷的工具。

| 特征 | 说明 |
| --- | --- |
| 多模态（Multimodal） | 综合运用语音、视觉、触觉等多种沟通渠道，还原真实交流体验。 |
| 自然语言理解（NLU） | 精准捕捉并理解复杂的自然语言意图、上下文语境及隐含情感。 |
| 情境感知（Context-Aware） | 实时感知物理环境、用户状态与任务背景，做出恰当的反应。 |
| 情感化（Emotional） | 具备识别并表达情绪的能力，与用户建立深层情感连接与共鸣。 |
| 主动性（Proactive） | 不仅被动响应指令，更能主动预测需求、发起交互并提供帮助。 |

### 语音功能的可拓展性

| 功能 | 核心能力 | 关键特性 |
| --- | --- | --- |
| 语音合成（TTS） | 文本转语音 | 多语言支持、情感语音、优先级管理 |
| 语音识别（ASR） | 语音转文本 | 实时识别、多语言支持、音频流处理（待开放） |
| 音频处理 | 信号优化 | 实时降噪、语音活动检测（VAD）、流式传输 |
| 音频播放 | 音频内容输出 | 音频流播放、优先级控制、多格式支持 |
| 音量控制 | 语音交互体验管理 | 音量调节、静音控制、〔末项前部被遮挡〕量查询 |

## 理解与勘误

### HRI 的功能

人机交互以语音、视觉、触摸、屏幕和灯光表达输入、处理中、执行与错误状态。屏幕表情和灯带是输出方式，不能据此断言机器人理解情绪或产生情感。

自然交互需要清晰反馈：收到指令、正在识别、任务被拒绝、执行成功或失败。播报一句成功不能代替确认底层结果。

### TTS 服务

`play_tts.py` 创建 `PlayTts` 客户端，等待 `/aimdk_5Fmsgs/srv/PlayTts`，封装文本与播放属性，异步调用并检查返回。实际命名需以服务列表与 SDK 类型核对。

请求包括文本、domain、trace_id、中断标记和优先级字段。课件示例优先级 6，是该接口配置，不是 ROS 通用优先级。服务响应成功常表示请求被接受，并不必然证明扬声器已播完。

```Bash
cd Embodied_Artificial_Intelligence/aimdk
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
ros2 run py_examples play_tts
```

### 本地识别与模型对话

课程练习为语音输入 → 本地转写 → LLM → 机器人 TTS。示例用 faster-whisper small、CPU/int8，本地模型路径是作者设备缓存，不可在别的电脑直接使用。

录音完成后进行必要重采样与通道处理，ASR 转文字，LLM 根据上下文生成中文回复，再 TTS。资料有回车开始/停止录音、`/reset` 清空对话和 Ctrl+C 退出的交互。CPU 可运行不代表任意长度都实时。

LLM 通过 OpenAI 兼容客户端接入千问服务。这是兼容 API 协议，不表示调用 OpenAI 模型。配置 base_url、model 和密钥；公开文档中密钥采用环境变量或占位符，不保留真实值。硬编码缓存路径、网络异常、录音设备缺失和接口超时需要处理。

### 回调和重试的限制

长时间录音、推理或 TTS 请求会阻塞执行线程，应避免影响控制回调。TTS 示例最多 8 次短超时重试；同一播报可能已经被接受但响应迟到，重试会造成重复，需要 trace/status 机制或幂等处理。

资料中的 `spin_until_future_complete` 用法要结合执行器上下文，不能在所有回调中直接照搬。收到 Ctrl+C 时应释放录音流、会话、节点和必要控制状态。

### 表情屏

`play_emoji` 连接 `/face_ui_proxy/play_emoji`，请求 emoji、单次/循环播放和优先级。课件示例 ID 包括眨眼 1、无聊 60、异常 70、睡眠 80、开心 90、双怒 190、崇拜 200，具体资源以当前版本为准。

屏幕可表现机器人状态并提供操作反馈。表情循环需要退出或被高优先级状态覆盖，不应让旧表情遮蔽当前错误。

```Bash
cd Embodied_Artificial_Intelligence/aimdk
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash
ros2 run py_examples play_emoji 
```

### 灯带

`play_lights` 使用 `LedStripCommand`，填写模式和 RGB。课件说明响应可能较慢，采用最多 4 次、约 5 s 超时的尝试。颜色、模式、数值范围和可中断行为应查实际接口，不能凭 UI 颜色猜代码。

灯光可以表示待机、聆听、思考、完成或故障，应明确含义并与语音/屏幕状态一致。灯带成功响应不等于运动任务完成。

```Bash
cd Embodied_Artificial_Intelligence/aimdk
source /opt/ros/humble/setup.bash
colcon build
source install/setup.bash

ros2 run py_examples play_lights 
```
