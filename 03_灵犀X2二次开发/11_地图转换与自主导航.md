## 重点概念

### ROS 2 Navigation2（Nav2）

为了实现机器人的自主导航，我们采用ROS2官方提供的强大模块化框架——Navigation2（Nav2）。它将复杂的自主移动任务拆解为一系列相互协作的独立组件，形成一条逻辑清晰、分工明确的“导航流水线”。

**接收目标**：用户通过RViz2或其他控制界面，为机器人设定一个明确的目标位姿，作为导航系统的输入指令。

**全局规划**：基于预先构建好的静态环境地图，利用路径搜索算法计算出一条从当前位置到目标点的宏观最优路径。

**局部规划**：融合激光雷达、IMU等实时传感器数据，动态调整机器人的速度指令，灵活避开沿途的未知障碍物。

**执行控制**：将局部规划生成的运动指令，转化为机器人底层的控制算法，最终驱动机器人精准到达目的地。

### Nav2 核心节点

map_server：负责加载静态地图（通常由map_saver生成）。

planner_server：负责全局路径规划（Global Planning）。它根据地图和目的地计算一条最优路径。

controller_server：负责局部路径规划（Local Planning）和运动控制。它接收全局路径，并生成速度指令（cmd_vel）以驱动机器人沿着路径行驶，同时避开动态障碍物。

### Nav2 生命周期管理

lifecycle_manager：这是Nav2的管理者。ROS2中的Nav2节点大多是“生命周期节点”（Lifecycle Nodes），它们不会一启动就立即运行，而是处于非活动状态。

## 理解与勘误

### 为什么做地图转换

课程采用二维代价地图规划，三维点云需经过滤波、占用建模和投影。点云不是天然不能导航，Nav2 也不是完全不能读取点云：其障碍层等可以使用 PointCloud2，而常用规划器在二维代价地图上工作。

Nav2 不必对每个点赋语义类别才能避障，几何占用与可通行分析即可发挥作用。课件点云没有语义、所以不能直接用于导航是该简化工作流的解释，不宜当作普遍定理。

### OctoMap 与二维投影

OctoMap 用八叉树表达三维占用，以射线与观测更新占用概率，区分占用、自由和未知。投影到二维时需要选适用高度，保留可能与机器人身体相撞的障碍，合理处理地面和天花板。

课件分别启动 `spark_fast_lio octomap_agibot.launch.py` 和 `octomap.launch.py`，在 RViz 查看结果，再保存 projected 地图。启动前检查两个 launch 的职责，避免重复节点或话题冲突。

保存产物为图像与 YAML，原资料分别出现 `projectedmap.pgm` 与 `projected.yaml` 命名，实际应以生成文件及 YAML 的 image 指向为准。地图原点、分辨率、旋转与三维定位图一致。

最终回看课件后，确认原课件命令为：

```bash
ros2 run nav2_map_server map_saver_cli -f ~/projected_map --ros-args -r map:=/projected_map
```

其中 `-f` 指输出前缀，`-r` 将保存器输入 `map` 重映射到课件栅格话题。先确认该话题实际存在且类型正确。这一前缀通常生成 `projected_map.pgm` 和 `projected_map.yaml`；课件说明又写 `projected.yaml`，与命令前缀不一致，以实际生成文件为准。资料要求把产物复制到导航包 `maps` 目录，再检查 YAML 的 `image` 与 launch 引用。此处只是恢复原照片中可读文字，没有执行保存命令。

### Nav2 组件

map_server 加载静态地图，planner_server 规划全局路线，controller_server 跟踪路径并产生速度，behavior_server 执行恢复行为，waypoint_follower 组织多航点任务，导航行为树组织过程，lifecycle_manager 管理配置与激活。

生命周期节点启动不等于已 active。需要检查 configure/activate 是否成功、地图是否加载、TF 和里程计是否可用。课件 launch 截图片段列出若干节点，但不能据此保证完整导航行为树接口已正常。

### 定位与导航的坐标链

常用 TF 为 map → odom → base_link → sensor。各边应有唯一责任方，时间戳可用。点云定位可以替代某些定位配置，但不能在同一系统重复运行多个同时控制 map→odom 的模块。

全局地图、局部代价地图、传感器外参和 footprint 都影响导航。人形 footprint 不只两脚占地；摆腿、手臂和转身范围需要考虑。二维规划不自动解决台阶和地面支撑可行性。

### 从 Nav2 速度到 X2

课件入口为：

```bash
ros2 launch my_nav2_pointcloud_pkg nav2_bringup.launch.py
ros2 run my_nav2_pointcloud_pkg cmd_to_aim_vel
```

后一节点把导航速度接入 X2 SDK，需注册输入源，设置 source、优先级、时间与超时。Twist 到自定义 McLocomotionVelocity 不只是改消息名，还需检查横移、单位、范围、频率和停止。

RViz 中设置目标后，机器人是否开始运动取决于导航已激活、定位有效、速度转换和控制权。第一次应按课程近距离验证原则检查运动方向、停止与避障，不能仅凭路径显示就进入长距离自动运行。

### 多目标加指定动作练习

课件要求按顺序导航到地图点并执行动作。状态机应包括选目标、提交、等待反馈、判断结果、执行动作、等待完成、进入下一点，以及失败/取消处理。

在 ROS 2 常用 `NavigateToPose` 或多航点接口。目标接受不是到达，位置容差内也需要考虑朝向和速度停止。动作服务返回 RUNNING 时应继续观察完成，不能立即提交下一目标。

目标点需要在地图范围内，动作执行时的姿态与周围空间满足要求。机器人实际执行状态应反馈给上层，模型或脚本中的一行成功日志不是完整任务成功证据。

### Nav2 的准确职责

全局规划不一定保证全局最优，结果取决于规划器、代价地图和约束。controller_server 主要通过控制器插件跟踪路径并生成速度；IMU 等传感器通常先参与状态估计，而不是每个控制器直接融合全部原始传感器数据。

生命周期节点的典型初始状态为 unconfigured，经过 configure 后进入 inactive，再经过 activate 进入 active。课件直接说启动后处于非活动状态，是对完整状态流程的简化。map_server 加载地图，map_saver 保存地图，两者职责不同。参考 [Nav2 生命周期说明](https://docs.nav2.org/jazzy/getting_started/navigation_concepts/ros2/)。
