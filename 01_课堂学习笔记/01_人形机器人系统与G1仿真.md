# 第一章：人形机器人系统与 G1 仿真

作者：**Mengyuan Wang**。这是我在上课及实验过程中整理的学习笔记，用于复习与交流分享。

本章记录人形机器人系统、G1 仿真与作业实践。硬件和技术示例按授课时的版本理解。

## 1. 本章在整个系统中的位置

人形机器人由机械、电气、传感、计算和控制系统共同组成。类似人的外形不能直接保证类似人的运动和任务能力；理解机器人应同时看身体结构、动作能力、感知与任务执行。

本课程的主线是先让 G1 在仿真中受控运动，再接入建图定位、规划避障、自主探索、目标检测、视觉定位和语言交互。

```text
用户目标 → 任务决策 → 规划 → 运动控制 → 电机与身体
                         ↑                ↓
                   状态与环境估计 ← 传感器
```

每个箭头都需要明确数据类型、坐标系、时间和更新频率。任务完成需要真实反馈，不能仅由程序打印成功判断。

## 2. 发展历史与课件中的机器人示例

课件用早期研究原型、能够持续行走的整机、具有更丰富运动与操作能力的系统，说明人形机器人发展过程。WABOT、WABIAN、ASIMO、SDR、Atlas 和 Optimus 等是其中的展示实例。

课件还列举 Walker X、CyberOne、GR-1、Unitree H1/G1、远征 A1、PX5、Figure 01、STAR1、NEO 和开普勒等产品。该部分用于认识不同研发路线，不将课件中的价格、上市时间和横向性能表作为当前产品比较依据；不同型号、配置和测试条件必须分别核对。

发展中反复出现的工程约束包括关节输出能力、整机重量、电池续航、传感盲区、计算资源、动态接触建模和可靠性。增加算力不能直接解决执行器不足，增加训练数据也不能自动修复错误的硬件接口。

## 3. 运动、操作和全身协调

### 3.1 双足运动与导航

双足运动关注站立、行走、奔跑、跳跃和地形适应。导航关注到达目标，通常输出路线或机体运动命令，再由底层控制实现稳定运动。

复杂地形中的导航还需要地形分析、可达落脚点和身体稳定性约束。对于社会动态场景，需要观察行人运动并处理不断变化的通行空间。

### 3.2 操作与运动操作

操作 Manipulation 改变外部物体状态，例如抓取或推动。运动 Locomotion 改变机器人自身位置。运动操作 Loco-manipulation 把两者结合，例如搬着物体走路或推车移动。

全身运动操作需要协调腿、身体、手臂和接触。在搬运时，物体改变负载与质心；推车时，手部接触力会影响身体平衡，不能独立调好手臂和腿就默认整体可行。

### 3.3 WBC、MPC 和多接触规划

全身控制 WBC 将身体、末端和关节任务协调为可执行的关节控制量。可采用解析方法、带权优化或分层优化，处理接触、动力学、关节限位与任务冲突。

模型预测控制 MPC 在有限预测时域内优化未来状态和控制，执行当前一步后，根据新状态重新规划。模型越完整，通常需要更多计算；简化模型计算方便，但可能忽略关节与接触细节。

多接触规划需要决定在哪里接触、何时建立或解除接触、怎样分配作用力。接触切换引入离散选择，连续运动又包含非线性约束，这是问题困难的主要来源。

## 4. 技能学习与基础模型

### 4.1 强化学习、模仿学习与迁移

强化学习 RL 从交互和奖励学习策略。模仿学习 IL 利用专家演示学习行为，数据可能来自机器人遥操作、运动捕捉或人类视频。

人类动作不能直接照搬到机器人，需要进行运动重定向，处理尺寸、关节结构、限位与接触差异。策略既可以表示为模型和权重，也可以与参考轨迹、状态机共同组织。

Sim2Real 的常见处理思路包括：

| 方法 | 主要作用 |
|---|---|
| 域随机化 | 训练中变化质量、摩擦、噪声或执行器等条件 |
| 系统辨识 | 根据实际输入输出修正模型或参数 |
| 域适应 | 利用目标环境数据改善策略适应性 |
| 分阶段验证 | 从训练仿真到另一仿真，再逐步验证真实系统 |

这些方法减轻迁移差异，不能代替关节顺序、控制模式和时间配置的核对。

### 4.2 GAIL、AMP 与混合学习

GAIL 用判别器区分专家与策略产生的数据，并把判别信息用于策略学习。AMP 利用参考运动构造运动风格相关的学习信号，帮助策略生成接近参考运动分布的行为。

两者都涉及对抗学习，但不能把课件列举的某种网络逐步扩展、缓冲区平衡或自模仿技巧写成 AMP 的统一定义。

RL 与 IL 可以组合：先模仿再用 RL 改善；先训练具有特权信息的教师，再让使用可部署观测的学生学习；或由 MPC、轨迹优化提供参考，策略学习跟踪或残差修正。

### 4.3 多技能与潜在表示

混合专家 MoE 用多个专家及选择或混合机制表达不同技能。选择失衡时，某些专家可能很少被使用。

潜在运动表示把高维动作编码到较低维表示中；目标表示把图像或语言目标编码为特征；世界模型学习状态转移关系。学习到一个表示，不代表已经保证动力学可行与任务安全。

### 4.4 LLM、VLM、VLA 与课程研究实例

LLM 处理语言；VLM 联合视觉和语言；VLA 把动作建模也纳入系统。基础模型可调用已有技能、辅助规划，也可以通过机器人数据训练更直接的动作策略。

课件展示了 NaVILA、ASAP、OMOMO、VLM-PC、HYPERmotion、GO-1、GR00T N1 和 OmniH2O 等实例。它们分别涉及导航、动作迁移、人与物体交互、语言或视觉条件规划以及多技能控制，不能仅凭展示效果判断任意场景中的能力。

课件中的 GR00T 示意图把视觉、语言和机器人状态作为条件，动作生成模块输出动作表示；GO-1 示意图涉及潜在动作与动作专家。这里保留系统角色的文字解释，不根据示意图推测未说明的训练细节。

## 5. G1 硬件组成

### 5.1 身体与自由度

课件描述了 G1/G1-EDU 不同配置。单腿示例为髋部三个自由度、膝部一个、踝部两个；手臂、腰部和灵巧手会随版本变化。整机的关节排列必须按实际模型确定，不能将课程中腿部策略的 12 个动作等同于整机所有自由度。

踝关节采用并联机构，PR 模式表达 Pitch/Roll 方向控制，AB 模式直接涉及相应执行电机。使用 AB 模式时，需要对应的机构运动学；两种表示不能直接逐项替换。

### 5.2 感知、计算与接口

| 部分 | 课件中的示例 | 学习重点 |
|---|---|---|
| 雷达 | Livox MID360 | 视场角、盲区、安装坐标和点云时间 |
| 深度相机 | RealSense D435i | RGB、红外双目、深度和 IMU |
| 音频与显示 | 麦克风阵列、扬声器、灯带 | 语音输入输出和状态反馈 |
| 运控计算单元 PC1 | 厂商运动控制 | 区分封装好的底层服务与开发接口 |
| 开发计算单元 PC2 | Jetson Orin NX | 承载开发者程序，也可使用外部 PC |
| 电源与外设 | 电池、电源输出、RJ45、USB、GPIO | 电气规格与网络接口需要单独核对 |

课件给出电池容量、续航、接口供电与计算单元规格。它们属于对应型号的历史配置，不能当作所有 G1 版本的统一接线依据。外接设备必须根据实际接口文档核对电压、电流与引脚。

两个传感器视场角相加也不代表全空间无盲区：遮挡、有效量程、安装角度和观测类型仍不同。

## 6. 软件架构与开发接口

### 6.1 SDK、ROS 与 DDS

`unitree_sdk2` 封装底层电机、高层运动及相关服务。DDS 是发布订阅通信规范及相应实现体系，ROS 2 可以通过中间件与对应接口集成。使用同一种中间件并不代表任意消息能自动互通，还要匹配域、类型、QoS 和网络配置。

课程软件结构中的 App、云服务、PC1、PC2 和外部 PC 承担不同职责。开发程序不必通过云端完成全部控制，但具体能力以开放接口为准。

### 6.2 底层与高层服务

| 接口层级 | 示例 | 含义 |
|---|---|---|
| 底层状态 | `rt/lowstate` | IMU、关节等机器人状态 |
| 底层命令 | `rt/lowcmd` | 关节控制与对应设备命令 |
| 灵巧手 | 左右手命令、状态话题 | 与全身关节接口分别组织 |
| 里程计 | `rt/odommodestate`、低频版本 | 位置、姿态、速度等状态 |
| 高层 RPC | 模式、站立、移动 | 调用已有运动功能 |
| 音频与灯光 | ASR、TTS、音量、灯带 | 输入输出与交互反馈 |

课件给出的里程计更新率为对应服务配置。运行时应测量实际接收频率，不能以标称频率替代通信检查。

高层接口适合调用已有运动能力；底层接口需要开发者承担更多控制与状态管理。模式切换、站立、停止、零力矩和阻尼各有不同含义。

### 6.3 手臂动作组织

课件展示读取当前关节姿态、记录动作目标、加入动作表、按序执行动作的方法。应使用平滑插值和适当速度，而不是瞬间发送大幅度关节跳变。读取当前姿态与执行该姿态之间也需要考虑机器人模式及当前状态。

## 7. 仿真平台与课程控制架构

| 工具 | 主要作用 |
|---|---|
| Isaac Gym | GPU 并行物理仿真与强化学习交互 |
| Isaac Sim / Isaac Lab | 仿真与机器人学习工具链，具体关系按相应版本理解 |
| MuJoCo | 多体动力学、接触和控制仿真，常用作跨仿真验证 |
| Gazebo | 机器人、传感器、场景及 ROS 插件仿真 |
| RViz | 观察模型、TF、传感器、地图和规划结果 |

仿真引擎、算法库、机器人模型和控制器不是同一层。RViz 的关节运动显示不等于物理仿真中机器人已稳定站立。

本课程中，`unitree_ros` 组织 Gazebo、G1 模型与关节控制插件；`unitree_guide` 组织 IO、策略推理和状态机。`robocup_g1` 是用于课程实验的工作空间或代码集合。

## 8. 第一章实验流程与作业

课程环境为 Ubuntu 20.04、ROS 1 Noetic、ROS 2 Foxy。G1 基础仿真实验主要使用 ROS 1 与 Gazebo。个人 Docker 方案见 [环境配置与 ROS 桥接](<../04_环境配置教程/00_Docker Ubuntu20.04 ROS1 版本为 Noetic，ROS2 版本为Foxy环境配置.md>)。

1. 按实践手册配置 ROS、Gazebo 和依赖，包括对应 Eigen 版本。
2. 在 `robocup_g1` 中构建并加载 `devel/setup.bash`。
3. 检查手柄是否被主机和容器识别。
4. 一个终端启动 Gazebo，另一个启动 `junior_ctrl`。
5. 按课程控制程序的状态切换流程使机器人进入准备与站立状态，再进行遥控。
6. 保存运行环境、关键命令、控制过程和演示结果。

作业讲解中的按键 2、暂停仿真、重置模型姿态、按键 4、恢复播放，是特定仿真代码的恢复操作，不应迁移为真机开机流程。

必选任务是使用 Xbox 手柄控制机器人行走并录制视频，整理安装和控制笔记。编译失败、模型找不到、灰屏或卡顿，需要分别检查依赖、模型路径、图形显示、GPU 和控制程序输出。

## 课堂补充：研究架构与仿真模型的区别

这一部分补全理论 p10、p13–15、p34–35 中原先只概述的关系。

Sim-to-Lab-to-Real 是课上展示的一种分阶段迁移研究思路：先在仿真预训练多样策略，在受控实验环境中适应，再讨论到未见真实环境的迁移。展示方案中使用 Hamilton–Jacobi 可达性相关的安全价值估计和监督控制来屏蔽部分不安全行为，并用 PAC-Bayes 框架讨论性能或安全性下界。它们依赖模型、数据与理论假设，不是任意人形机器人的通用安全保证，也不是本仓库完成的实验。

GO-1 示意图称为 Vision-Language-Latent-Action（ViLLA）：视觉语言模块使用课件所列 InternVL-2B，潜在规划模块 LatentPlanner 与动作专家 ActionExpert 分工。示意图包含从视频重建潜在动作、潜在规划、动作片段生成等阶段。潜在动作 token 是模型内部表示，不能直接当成已知单位的关节角；最后仍需机器人动作数据及对应执行模块。

Helix 示意图区分较慢的语义推理与较快的反应控制，GR00T N1 示意图区分视觉语言处理与扩散式动作生成；后者还输入机器人关节及身体状态。这里只记录课堂图中模块职责，不沿用图内不同频率标注作为实测参数。Helix 的原推荐链接错指 GO-1，不能作为 Helix 的有效参考。

仿真建模与训练框架要分层看：Isaac Gym 提供 GPU 张量接口、物理状态、传感器、参数随机化与雅可比等工具；PPO、Stable-Baselines3、RLlib 等负责算法组织；ROS 负责程序间接口。Isaac Lab 与 Isaac Sim 的具体依赖按版本说明核对，不能由课堂概括表推导 Lab 在所有版本中都独立于 Sim，或必然需要更低算力。

MuJoCo 模型输入可以是 MJCF/受支持的 URDF、程序构造的 `mjSpec`，或预编译的 MJB；编译/加载后得到 `mjModel`，运行状态保存在 `mjData`。模型结构、运行状态和神经网络权重是不同对象。`mjData` 的职责为整理补充，已核对 [MuJoCo 官方初始化说明](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#initialization)。`mjSpec` 等接口需结合实际 MuJoCo 版本使用。课堂还介绍广义坐标、接触、肌腱与驱动模型，不能把 MuJoCo 只理解成一个模型展示窗口。

历史硬件表的阅读也要区分内存类型：PC2 所列 Jetson Orin NX 为 16 GB 配置，其 CPU/GPU 使用共享内存，不能把表中内存 16 GB、显存 16 GB 相加当成 32 GB 独立存储。共享 SoC DRAM 的解释为整理补充，已核对 [NVIDIA Tegra 内存说明](https://docs.nvidia.com/cuda/cuda-for-tegra-appnote/index.html#memory-management)。电池表记录 13 串、9000 mAh、约 2 h，为授课机型示例，容量单位不等于能量或固定续航；外设电源输出与 GPIO 引脚须按实际硬件文档核对。
