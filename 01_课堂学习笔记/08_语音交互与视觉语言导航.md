# 第八章：语音交互、语言导航与 NaVid

作者：**Mengyuan Wang**。这是我在上课及实验过程中整理的学习笔记，用于复习与交流分享。 个人实现见 [第八章作业参考](../02_作业参考笔记/08_语音交互与导航.md)。

## 1. 大模型在机器人中的位置

LLM 处理语言，VLM 联合理解视觉与语言，VLA 将视觉语言与动作输出连接。课程展示三种连接方式：大模型生成任务/代码后调用已有技能；视觉语言条件决定技能选择；模型直接输出某一层动作。

任务计划、速度命令、关节目标与力矩是不同控制层。语言模型输出一句前进，并不等于已经生成稳定步态。底层仍需要感知、状态估计、运动控制与执行反馈。

云端服务省去本地模型部署，但依赖网络、鉴权及服务延迟；端侧或本地服务器需要计算与模型环境。课件的阿里百炼、火山方舟产品界面和免费额度是授课时展示，不作为当前价格或可用性说明。

## 2. ASR、LLM、TTS 的链路

ASR 把语音转成文本，LLM 产生回复或任务指令，TTS 把回复转成语音。课程 demo 用电脑麦克风和扬声器完成仿真人机对话：音频采集 → ASR → 对话上下文/Prompt → LLM → TTS → 播放。

音频采样率、通道、编码和分块必须符合服务协议。将 WAV 文件完整字节直接当 PCM 发送可能把文件头也送入识别。播放语音可能被麦克风重新采集，需要录放状态或回声处理。阻塞的网络调用不能长期占用机器人控制回调。

工程可分为客户端鉴权、音频输入、识别、会话管理、模型请求、语音合成和播放。课件提供服务开通和鉴权视频，实际密钥不应写在可上传文件中，可从环境变量读取。

```python
import os

api_key = os.environ["ROBOT_LLM_API_KEY"]
```

这是整理补充的配置方式，不是对某家服务完整 SDK 调用的替代。原笔记的密钥字面值已脱敏。

## 3. 从说话到目标导航

课程作业给地点建立地图坐标，例如直播间对应某点，再在 `prompt.py` 中配置，要求模型输出 `Nav(x,y)`。这个文本协议本身没有运动能力，需在 `demo.py` 中解析、验证、构造 ROS 导航目标并发布。

本地 `shenlan_ai` 基础 demo 的核心是 ASR/LLM/TTS；接入导航属于作业扩展。作者笔记记录了后续 ROS 目标发布代码，不能将扩展能力归给未经修改的原 demo。

完整执行链为：识别意图 → 选地点 → 验证目标 → 导航接口提交 → 等待/取消/失败处理 → 向用户反馈。地点表必须绑定当前地图和 `frame_id`。超出地图、目标不可达、定位失效或指令模糊时，应返回明确状态。

自由文本解析容易受多余文字、格式变化和错误坐标影响。可使用结构化参数或 function calling，将可调用动作限制为已定义功能。RAG 给模型提供地点与任务资料，记忆维持对话上下文；二者都不能替代目标合法性和执行反馈。

ROS 1 常见导航 action 与 ROS 2 Nav2 接口不同。课程 ROS 1 的发布方式应放在原环境复现；新 ROS 2 工程应使用对应 `NavigateToPose` action 或已定义接口，不能混用包名和消息。

## 4. VLN 的任务含义

Vision-and-Language Navigation 根据自然语言与视觉观测寻找路线。指令可能包含转弯、经过地标和停止条件。与固定坐标导航相比，系统还要把语义描述与真实场景关联。

离散 VLN 在图节点间移动；连续环境 VLN 需要真实运动及碰撞约束。ObjectNav 指定目标类别，跟随任务追随动态对象，具身问答可能在探索后回答问题。课件把这些作为相关任务展示，不能将所有任务统称为同一个评测协议。

## 5. NaVid 的输入、模型与输出

NaVid 使用语言指令、历史视频帧和当前帧预测下一步导航动作。课程强调其高层视觉导航输入不依赖显式地图、深度或里程计；这一点不表示机器人底层控制完全不需要自身状态。

框架基于视频视觉语言模型：图像编码器产生视觉特征，文本查询提取与指令相关的信息，池化提供与指令无关的视觉概况；历史、当前观测与导航指令通过特殊标记区分，再送入语言模型预测动作。

课件出现 `<HIS>`、`<OBS>`、`<NAV>` 等标记，作用是组织输入，实际格式取决于源码。动作包括前进、左转、右转和停止，课程图也展示动作附带距离或角度。执行端须把这些动作映射到速度/运动技能，限制动作时长并反馈完成状态。

LLaMA-VID 是视频/图像多模态框架；NaVid 在其基础上面向导航训练，二者不能直接等同。课程使用 VLN-CE/R2R 相关专家轨迹、非专家数据和视频问答进行联合训练；具体配比与训练细节要查原论文和源码，课件没有完整提供。

## 6. Uni-NaVid 与 NaVILA

Uni-NaVid 在课程中展示统一导航、物体搜索、跟随和问答的思路，利用历史记忆与视觉 token 合并减少处理负担。NaVILA 展示高层视觉语言动作与低层腿式运动策略分工：高层给运动指令，低层结合关节、姿态、历史动作和地形信息生成关节目标。

课程画面用于说明研究方向，不代表本仓库已经部署这些模型。网络资料可用于补充论文阅读，但不存在的本地权重、数据集或部署脚本不补写为已完成。

## 7. 部署与实验边界

NaVid 课程安装示例含 Python 3.8、Habitat-Sim/Habitat-Lab 0.1.7、源码依赖与预训练权重目录。它们是对应历史工程组合，升级某一项可能破坏兼容性。课程源码入口为 [NaVid-VLN-CE](https://github.com/jzhzhang/NaVid-VLN-CE)，项目展示入口为 [NaVid](https://pku-epic.github.io/NaVid/)。这两个链接来自课件，本次未逐项验证当前安装可用性。

机器人端还要处理摄像头频率、历史帧缓存、推理延迟、动作执行时间和停止条件。只显示模型输出不等于闭环导航成功。应保存输入、预测动作、执行结果和失败类型。

## 8. 作业与复习问题

基础作业是开通课程所用模型服务、按示例配置运行环境，实现对话。扩展要求记录地图地点，配置 Prompt，修改 demo 将导航文本变成目标发布，实现语音加目标导航。

复习时应能解释：哪一层识别语言，哪一层选择目标，谁保证定位和避障，模型出错怎样停止，机器人怎样报告到达。这些问题可以直接用于入门报告的系统讲解。

## 语言导航补充：任务分类与两个研究框架

对应理论 p12–16。课堂区分按指令导航、按目标搜索、按抽象需求寻找地点：例如先经过门口再左转、寻找指定物体、根据我饿了推断可能需要寻找餐饮地点。任务输入与完成条件不同，模糊需求还需要澄清或额外任务知识，不能直接把一句需求变成无条件运动。

R2R、REVERIE、Find What You Want、HM3D、citywalker 和 AerialVLN 在课堂中作为任务/场景示例出现，分别涉及室内指令、远程目标、偏好或需求、室内三维环境、室外以及空中导航。这里记录区别，不新增未经本地材料给出的数据规模或分数。离散环境与连续环境还应分别说明动作空间和评价协议。

Uni-NaVid 图中将历史视频分成长期与短期记忆，并保留当前观测，通过在线视觉 token 合并和网格池化控制输入规模。压缩减少计算和上下文长度，但可能损失细节，不等于记住全部历史。NaVILA 的数据流程图还列出视频轨迹采样、度量位姿估计、VLM 描述、LLM 改写与逐步动作；执行端由 VLA 生成可解释的移动指令，再交低层腿式策略产生关节目标。两者的数据构造和控制层次不同，不能只统称为视频模型直接控制电机。
