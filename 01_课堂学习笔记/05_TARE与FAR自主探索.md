# 第五章：TARE、FAR 与机器人自主探索

作者：**Mengyuan Wang**。这是我在上课及实验过程中整理的学习笔记，用于复习与交流分享。 个人适配见 [第五章作业参考](../02_作业参考笔记/05_TARE与FAR自主探索.md)。

## 1. 导航目标从哪里来

点到点导航的终点由人给出；自主探索需要机器人自行选择下一个值得观察且能够到达的位置。它同时维护地图、估计位置、判断可通行区域、选择视点并执行路径，目标是逐步覆盖未知区域。

课程背景包括地下设施、危险场景和复杂三维环境。导航与建图并非必须先后独立完成，可以用局部已有信息规划，边移动边扩展地图。未知区域不应直接被当作安全空间。

## 2. 系统架构与接口

课程采用 CMU 自主探索开发环境。顶层规划器输出航点、速度和边界；中间层进行地形分析、局部规划与航点跟随；底层提供定位点云和运动控制。TARE 侧重探索目标与覆盖路线，FAR 侧重已知或未知环境中的目标路线。它们可分别运行，也可经系统集成配合，并不是所有任务都必须串联二者。

| 接口 | 含义 | 需要检查 |
| --- | --- | --- |
| `state_estimation` | 机器人位姿估计 | frame、时间戳、是否把真值误当估计 |
| `registered_scan` | 配准后的扫描 | 地图坐标、噪声、更新频率 |
| `terrain_map` | 通行分析结果 | 高度基准、未知区、障碍阈值 |
| `way_point` | 上层航点 | 路点坐标及更新条件 |
| `navigation_speed` | 自主模式速度输入 | 单位、限幅和手动接管 |
| `cmd_vel` | 底层速度命令 | Twist/TwistStamped 与轴约定 |

课程示例环境为 Campus、Indoor、Garage、Tunnel、Forest，各自用于大范围、多层、曲折通道、起伏地形和细小障碍等测试。Matterport3D 与 Habitat 是课件对真实室内模型和视觉仿真的扩展介绍，不等于当前 G1 实验已经使用了这些数据集。

## 3. 局部规划器的离线路径库

课程 LocalPlanner 预生成短距离候选路径，以路径 ID 和组 ID 管理，保存 `startPaths.ply`、`paths.ply`、`pathList.ply`。示例路径范围约 1 m，角度范围 ±27°，组合数量为课程给定的 `343×7`，不是算法固定常数。

为了快速排除碰撞路径，离线建立体素与候选路径的对应关系，保存 `correspondences.txt`。运行时障碍物落入某体素，即可查询受影响的路径。该对应关系服务于碰撞筛选，不能简单理解成体素内列出的路径全部可通行。

课件示例 `voxelSize=0.02 m`、`searchRadius=0.55 m`、体素数量与偏移是生成路径库时的配置。改变机器人尺寸或路径缩放后，要检查对应关系是否仍有效。表格中机体长宽是课程局部模型，不能直接代表完整 G1 躯体与摆臂范围。

运行参数包括是否允许倒车、自主模式、最大速度、地形分析、旋转碰撞检查、障碍高度、相对高度筛选、方向权重、路径尺度和路径长度。按速度缩放路径会影响预测范围，但不能替代制动距离检查。

## 4. 航点跟随与地形分析

航点跟随器将路径转到局部坐标，寻找前视点，根据方向误差设置线速度和偏航角速度，再施加速度、加速度及安全停止限制。应先核对倾斜角、倾斜角速度、安全停止信号，再发布命令。前视距离过短容易抖动，过长可能切弯。

地形分析接收点云与里程计，维护体素、高程与时间信息，去地面并分类障碍，生成地形地图。静态结构、短期变化和没有观测的区域需要不同处理。地形中的噪点可能让狭窄通道被堵死；直接降低障碍阈值又可能漏检真障碍，应先检查坐标和离群点。

## 5. TARE 的分层覆盖规划

TARE 将远处环境用稀疏表达处理，将附近环境用稠密表达处理。全局层维护子空间状态 `unexplored`、`exploring`、`explored`，利用历史路径形成路网，确定未完成区域的访问顺序；局部层计算视点可见性、覆盖收益和精细路径，再连接全局与局部路线。

视点是传感器可观察环境的位置。某个表面是否被视点覆盖，取决于距离、视场、朝向、遮挡及传感器有效范围。不能仅用点与视点距离小于阈值断言可见。

候选视点生成后，计算每个视点新增覆盖量；反复选择视点并更新剩余收益。多个视点覆盖同一表面时不应重复计入新收益。课程用优先队列、覆盖奖励和重复采样说明这一过程。

访问顺序涉及旅行商问题。先根据可通行空间计算视点对之间的路径距离，再求访问顺序；距离矩阵不能只用穿过墙壁的直线长度。TSP 求解通常是近似或启发式，不应把工程求解结果称为全局最优证明。

局部路径再分段、平滑，课件使用三次样条与 NLopt 优化来处理转弯和碰撞约束。平滑后的轨迹需要重新碰撞检查，原离散路径安全不保证插值曲线安全。曲率限制是规划模型条件，人形机器人还需要底层行走能力匹配。

整体循环是更新环境与子空间、更新关键位姿图、生成视点、局部和全局规划、拼接路线、发布前视点、监控覆盖与返航条件。

## 6. FAR 的可见图

可见图的节点包含障碍物轮廓顶点及起终点。两节点之间的直线若不穿过障碍内部，可形成可见边。在理想二维多边形环境与点机器人条件下，该表达适合搜索几何短路径；实际点云、膨胀、简化轮廓和动力学约束会改变条件。

FAR 使用局部与全局两层图。局部层将点云投影并膨胀为图像，滤波、提取轮廓、简化顶点并剪枝；全局层将新轮廓与已有节点匹配，多帧过滤后更新节点和可见边，删除失效关系。对未知区域的可尝试路线，需要随着新观测重新判断通行性。

课程核心函数链包括 `BuildTerrainImgAndExtractContour()`、`MatchContourWithNavGraph()`、`UpdateContourGraph()`、`UpdateNavGraph()`。`surround_obs_cloud` 是周围障碍点云，`contour_graph_` 是中间轮廓图，`nav_graph_` 是可用于规划的导航图。

核心类的分工：ContourDetector 提取轮廓，MapHandler 管理地图与高程，ScanHandler 处理扫描，ContourGraph 管理轮廓关系，DynamicGraph 更新导航图，GraphPlanner 搜索路线。理解这些责任，比只记 launch 命令更有助于排错。

课件一处写 BFS，流程图又写 A*。若边成本为长度且长度不同，普通 BFS 只最小化边数，不能保证最短距离；应检查实际版本的加权搜索实现。笔记采用加权图搜索的表述，保留这一原资料矛盾。

## 7. G1 仿真适配

先独立验证开发环境、TARE 和 FAR，再连接 G1。课程 ROS 1 工作空间用 `catkin_make` 编译，ROS 2 则不使用这一构建方式。运行时分别 source 对应工作空间，避免多个版本叠加污染环境。

课程将 FAST-LIO 的 `/Odometry` 对接 `/state_estimation`，配准点云对接 `/registered_scan`，并连接 `camera_init`、`body` 与 `map`、`sensor`。重命名话题只改变名字，不改变消息坐标系和物理含义。静态 TF 应来自真实安装或仿真模型，零外参只在对应关系确实重合时成立。

速度接口需要检查接收端是否要 `TwistStamped`。如果只给 `Twist` 加一个 Header，仍要确认时间、轴向和控制模式。课程观察到配准点云噪声引入假障碍，建议做离群点过滤；过滤后应检查薄柱等真结构是否保留。

课程将探索结束条件中的 5 s 改为 1005 s，以避免过早结束。这只是延长时间判据，并不自动修复覆盖评估、图断连或回家条件。应同时记录结束触发条件和剩余未覆盖区域。

## 8. 实验与作业

作业是将 TARE/FAR 接入 G1 仿真，展示自主探索或目标导航，梳理状态估计、地形、航点、局部规划和运动接口。应分别测试手柄模式、自主模式、安全停止、返回起点和不可达目标。

衡量探索可记录覆盖比例、距离、耗时、重复经过量和停止原因。这里只给指标定义，没有把课程展示或个人截图当成当前复测结论。作者的 TF 适配、离群点处理和探索时间修改保留在参考笔记。

## 接口与调参补充：TwistStamped、转弯与半径滤波

对应作业讲解 p5–8。课程原机器人接收端为 `geometry_msgs/Twist`，规划器输出为 `geometry_msgs/TwistStamped`；两种消息类型不能只靠同名 `/cmd_vel` 连接。作业采用修改 `IOROS.h` 与 `IOROS.cpp` 接收回调、读取 `msg.twist` 的方式；也可使用独立转换节点提取 Twist，但要另外处理原消息时间、过期和停止，不能把增加 Header 当作适配的全部工作。

替换 Gazebo 后，需要关闭开发环境里重复的 `vehicle_simulator.launch`，保留 `loam_interface.launch` 及所需中层接口。TF 的零变换只适用于课程简化坐标重合，不是通用标定结果。

课程针对 G1 转弯容易摔倒降低 `maxYawRate`，并设置 `twoWayDrive=false` 禁止该局部规划器倒车。这些分别控制角速度上限与候选运动方向，不等于已经验证所有地形上的稳定性。

课上使用 PCL `RadiusOutlierRemoval`：搜索半径 0.2 m、半径内最少邻居数 5，删除过孤立的点。这是课程示例，不是所有点云固定参数；距离、点密度变化会影响邻居数，稀疏的细柱也可能被误删。这里保留了之前只写离群点过滤而没有说明的算法和参数。

### 第五章 群里相关资料

上一章介绍的 A*算法与 DWA（动态窗口法）在已知环境建模或局部动态避障场景中，具有非常大的工程价值，前者在当前地图上搜索路径，满足启发函数和搜索实现条件时可求最小代价路径；后者在局部可行速度中选择控制量，动态障碍还需要预测或及时更新。

然而，当面对地下管网勘探、灾后废墟搜救等一些完全未知且复杂多变的非结构化环境时，该方案的局限性就凸显出来了：A* 本身负责搜索，不负责建图；与在线建图配合仍可在未知环境中逐步规划。DWA 负责局部控制，也不提供完整的全局探索目标选择。这是任务分工的限制，不能概括为未知环境中 A* 无法启动。

这时候，就要求机器人具备集环境感知、地图构建与主动决策于一体的自主探索能力。本章会聚焦 CMU 团队研发的 TarePlanner 分层探索框架与 FarPlanner 动态可见性图算法，讲解如何通过全局策略规划与局部实时优化的协同机制，实现未知环境下的高效自主探索。
