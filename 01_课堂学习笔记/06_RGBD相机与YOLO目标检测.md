# 第六章：RGB-D 相机、YOLO 与足球场目标检测

作者：**Mengyuan Wang**。这是我在上课及实验过程中整理的学习笔记，用于复习与交流分享。 个人数据采集、训练对比及结果见 [第六章作业参考](../02_作业参考笔记/06_YOLO数据与训练.md)。

## 1. 感知在整套系统中的位置

课程使用摄像头识别足球、门柱和球场标线交点。检测回答图像中有什么、在哪里；深度和标定帮助得到三维位置；地图匹配再估计机器人位姿。检测框本身不是全局定位结果。

## 2. RGB-D 相机与深度原理

RGB 图像提供颜色和纹理，深度图为像素提供深度。常见深度方案包括双目、主动双目、结构光和 ToF。双目利用左右图像的视差，在理想平行双目条件下：

$$
Z=\frac{fB}{d}.
$$

$f$ 为像素单位焦距，$B$ 为基线，$d$ 为视差，$Z$ 为光轴方向深度。视差很小时深度对误差更敏感。主动双目通过投射纹理改善匹配；它与根据编码图案恢复深度的结构光方法有联系，但不能将所有 RealSense 相机都称为结构光相机。D435/D435i 属于主动双目产品线。

ToF 测量光传播时间或相位差，深度误差受材质、反射、距离、环境光及多径影响。不能给所有 ToF 或 RealSense 型号统一承诺亚毫米精度。课件提到的型号用于理解传感器选择，规格需按具体型号核对。

使用时检查彩色与深度是否对齐、CameraInfo 内参、畸变参数、图像编码和单位。常见 `16UC1` 深度与 `32FC1` 深度可能采用不同数值尺度，读取后应明确转为米；无效深度通常需要过滤。

## 3. YOLO 检测器的基本思路

YOLO 是一阶段目标检测系列：输入图像经过特征提取与多尺度融合，输出位置和类别预测，再按对应版本做后处理。课程以 YOLOv8 与 Ultralytics YOLO11 为比较对象。不同任务权重对应检测、分割、分类、姿态和旋转框，不能把同一个权重当作支持全部任务。

主干提取特征，颈部融合尺度，检测头预测类别与框。小目标依赖高分辨率细节，大目标依赖较大的感受范围。传统重叠框消除使用 NMS，但不同版本可能采用不同推理结构，不能推广为所有 YOLO 永远需要 NMS。

框交并比为：

$$
\operatorname{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

它衡量框的重叠程度，不是分类准确率。置信度过滤与 IoU 后处理阈值分别影响保留检测和去重。

## 4. YOLOv8 与 YOLO11 的课程比较及纠正

课程重点是 C2f 与 C3k2 的差异、SPPF 后的 C2PSA，以及速度、参数量、精度的权衡。网络结构应以对应代码配置为准，模型变大不保证在每个自建数据集上都更好。

课件将 C2PSA 中的 PSA 解释为 Pyramid Squeeze Attention，并配了相关示意。这与 Ultralytics 对该模块的实现不一致。整理时以官方结构中的部分自注意力模块解释 C2PSA，避免把另一个同名缩写机制混入 YOLO11。模型文件命名使用官方 `yolo11n.pt` 等，而不是照抄 OCR 中的 `yolov11n.pt`。

官方资料确认 YOLO11 的 C3k2 和 C2PSA 结构，详见 [Ultralytics 架构说明](https://docs.ultralytics.com/guides/yolo-architecture)。支持的任务和模型文件参见 [YOLO11 官方文档](https://docs.ultralytics.com/models/yolo11/)。以上是补充核对，课程流程仍以本地版本为准。

## 5. 仿真球场与传感器

课程球场约 9 m × 6 m，加载球场模型、门柱、标线、可移动足球与 G1。`earth.world` 组织世界，模型网格提供几何与外观，碰撞体决定物理接触，两者需要区分。

G1 安装水平和倾斜相机。课程水平彩色话题为 `/horizontal_camera/color/image_raw`，深度为 `/horizontal_camera/depth/image_raw`；另一路相机用于近处或俯视观察。图片、深度图和 PointCloud2 是不同消息类型，课件把某些显示项混写在同一个列表，实际话题应查询类型后再订阅。

COCO 预训练类别不能充分覆盖门柱及 L/T/X 标线，因此需要自定义训练。足球是否能由预训练模型识别取决于类别、视角与外观，不能保证每帧都能检测。

## 6. 从数据到训练

检测类别包含 Ball、Post、L、T、X。类别 ID 的顺序由数据 YAML 与标签共同决定，整理时不凭课件缺失行补写编号。新增数据应沿用实际工程的 `names` 顺序。

采集多个角度、距离、遮挡、光照与两种相机视角。第三人称图像可用于补充外观，但其分布与机载图像不同，验证应包括部署相机视角。课件一处写采集 104 张，后面划分图示写 96 与 18 张，总和不一致；这里保留这一差异，不将它当作已核实的数据集总数。

LabelImg 或 Roboflow 标注框与类别。YOLO 常用标签格式：

```text
class_id x_center y_center width height
```

后四项按图像宽高归一化，不是像素值。框应贴合目标并一致处理遮挡。漏标物体会在训练时被当成背景。标线交点的框中心是否代表定位关键点，需要在下一章专门处理。

将图像和标签成对划分训练、验证、必要时测试集。相邻视频帧不能随意拆入不同集合，否则验证可能过于乐观。新增图片后要核对路径、标签 ID、空标签与缓存。

## 7. 训练参数与指标

`epochs` 是最大训练轮数，`batch` 是每批样本数，`lr0` 是初始学习率，`lrf` 是末期学习率相对初始值的因子，`patience` 控制验证指标长期不改善时的提前停止。它们需要与数据规模、GPU 内存和模型配合，不能仅靠增加轮数解决标注问题。

训练曲线包括 box loss、cls loss、DFL loss，以及 precision、recall 和 mAP。精确率和召回率分别为：

$$
P=\frac{TP}{TP+FP},\qquad R=\frac{TP}{TP+FN}.
$$

AP 根据精确率与召回率的关系计算，mAP 再对类别平均。mAP50 使用 IoU 0.5，mAP50-95 对多个 IoU 阈值平均。单个框的置信度、整体 mAP 和分类准确率不能互换。

验证损失下降不等于定位误差下降。需要检查各类别表现、误检漏检、混淆矩阵、部署视角和速度。较大模型的课件基准是在特定硬件与数据协议下得到的，不能当作个人电脑实时性承诺。

示意训练代码，数据路径应替换为自己的已核对配置，参数仅用于展示调用方式：

```python
from ultralytics import YOLO

model = YOLO("yolo11n.pt")
model.train(data="dataset.yaml", epochs=100, imgsz=640)
```

具体课程参数、数据扩增与对照结果保存在个人笔记，不在此另造训练数值。

## 8. 推理与作业

推理节点接收图像、预处理、调用模型、提取框与类别，必要时结合深度发布检测或三维目标。OpenCV 展示、ROS 消息和保存视频分别承担不同责任。回调处理过慢会累积旧帧，应监测端到端延迟。

作业要求新增 20 张以上图像，包含平视和倾斜视角，完成标注与划分，再调整参数训练、查看指标、输出预测视频。比较扩增前后时应使用同一验证集；如果验证集也被改变，要同时报告评估口径，不能直接把两个 mAP 当成公平提升证明。

## 训练损失补充：Box、Cls 与 DFL 的职责

对应作业讲解 p8–9。Box loss 约束预测框与真实框的几何重合，Cls loss 约束类别预测，DFL（Distribution Focal Loss）用于框回归的离散距离分布学习，不是把框大概位置修好后另行执行一次边缘微调，也不能与用于分类难例加权的 Focal Loss 混为一谈。具体损失和权重以所用 YOLO11 版本为准。

补充理解：若一个边界距离目标 $y$ 位于相邻离散 bin $l$ 和 $l+1$ 之间，可分别以 $l+1-y$ 与 $y-l$ 加权两个位置的交叉熵，让概率分布表达连续目标。这里只解释 DFL 的职责，没有替代完整训练实现。已核对 [Ultralytics DFLoss 官方实现](https://docs.ultralytics.com/reference/utils/loss/#ultralytics.utils.loss.DFLoss)。

`runs/train/football_detection/` 是课堂结果目录示例。应把训练/验证损失、PR、各类别 AP、预测视频对应到同一模型编号。训练损失下降只说明当前训练目标被优化，不能直接证明泛化或三维定位精度提升。
