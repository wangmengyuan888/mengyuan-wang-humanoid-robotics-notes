#### 问题1：声卡问题

容器 `ros1_noetic` 里其实**能直接看到声卡**（`/dev/snd` 已透传进来），但有两个坑：

1. 原记录中直接打开的 ALSA 设备在尝试 16000/24000 Hz 时返回 `Invalid sample rate`，当时使用 48000 Hz 双声道及 PulseAudio 重采样。该结果只针对选定设备和配置，不能据此说整个 ALC287 硬件仅支持一种模式；也可检查 ALSA 插件、设备选择及其他重采样方案。

2. 容器里 PulseAudio 没启动，也没加载真实声卡（默认是 `auto_null` 假设备，录出来是静音）。

##### 做了什么

创建了 setup_audio.sh（放在 `shenlan_ai/` 目录，宿主机和容器都能看到，因为 `/home/mengyuan/ros1_ws` 就是挂载到容器 `/root/ros1_ws` 的）。它的作用：

- 设置 `PULSE_SERVER` / `PULSE_COOKIE` 环境变量（让 pyaudio 能连上系统级 PulseAudio）

- 若 PulseAudio 没运行，以 system 模式启动

- 把真实麦克风 `alsa_input.hw_1_0` 和扬声器 `alsa_output.hw_1_0` 加载进去

已验证：**录音 16000Hz（峰值 25957，真实麦克风）✅ 播放 24000Hz ✅**，且脚本幂等（连跑两次不会加载重复模块）。

##### 新建的 setup_audio.sh（音频初始化脚本）

```Bash
#!/bin/bash
# 容器内音频初始化脚本（每次进入容器后执行一次即可）

# 1) 让客户端(pyaudio/pactl)能找到系统级 PulseAudio 并完成鉴权
export PULSE_SERVER=unix:/var/run/pulse/native
export PULSE_COOKIE=/var/run/pulse/.config/pulse/cookie

# 2) 若 PulseAudio 尚未运行，则以 system 模式启动（root 只能用 system 模式）
if ! pactl info >/dev/null 2>&1; then
    pulseaudio --system --disallow-exit --exit-idle-time=-1 -D
    sleep 1
fi

# 3) 若真实麦克风/扬声器尚未加载，则加载到 PulseAudio
if ! pactl list sources short 2>/dev/null | grep -q alsa_input.hw_1_0; then
    pactl load-module module-alsa-source device=hw:1,0
fi
if ! pactl list sinks short 2>/dev/null | grep -q alsa_output.hw_1_0; then
    pactl load-module module-alsa-sink device=hw:1,0
fi

echo "[audio] 就绪：麦克风 alsa_input.hw_1_0 / 扬声器 alsa_output.hw_1_0"
```

作用：通过 PulseAudio 为当时选择的音频设备做采样率适配，使录音和播放接口按 ASR/TTS 所需格式工作。

```Plain Text
def publish_navigation_goal(self, x, y):
    goal = self.PoseStamped()
    goal.header.stamp = self.rospy.Time.now()
    goal.header.frame_id = "map"

    goal.pose.position.x = x
    goal.pose.position.y = y
    goal.pose.position.z = 0.0

    goal.pose.orientation.x = 0.0
    goal.pose.orientation.y = 0.0
    goal.pose.orientation.z = 0.0
    goal.pose.orientation.w = 1.0

    self.goal_publisher.publish(goal)
```

LLM 返回后会自动解析并发布：\`/home/mengyuan/ros1_ws/unit4_shenlan/shenlan_ai/demo.py:297`（原实验工程路径，未作为仓库附件）
